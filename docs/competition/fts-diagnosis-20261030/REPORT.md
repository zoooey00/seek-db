# 全文索引调优：最终排查与提交说明

**最终选择：IK + BENG 优化。本机六轮相对首次 FTS 修改前版本的综合均值变化为 +1.18%；正式平台结果尚未取得，不能宣称已达到性能目标或满分。**

## 已落实的修改

1. 撤回 `0668450` 新增的单次词频更新和 ASCII 停用词索引。16 轮拆分对照中，仅词频、仅停用词、两项同时启用的综合均值分别为 −4.10%、−4.36%、−5.04%，没有可靠的整机收益证据。
2. 保留 IK 字符分类、仲裁、词典及生命周期修复，并保留 BENG 分配优化。仅 IK 版没有显示足够可靠的优势，因此没有继续撤出已有 BENG 改动。最终相对首次 FTS 修改前版本涉及 12 个生产文件，不改动该分支已有 AI 功能。
3. 保留新增的词频、排序规则和停用词语义回归测试；修正测试输出和说明，避免将已撤回的实现继续描述为当前实现。
4. 用完整服务端完成三阶段共 **42 轮**新基准，并保留全部结果；之前八轮也保留在历史报告中。没有修改基准脚本、数据、SQL、计时逻辑、评分脚本、固定基线或工作流。

## 三阶段实验及决定

第一阶段为四版本 16 轮拆分对照；第二阶段为撤回两项新增优化后与首次 FTS 修改前版本的八轮比较。第二阶段综合均值为 −3.17%，分词退化较明显，因而增加第三阶段来验证 BENG 是否应撤出。前两阶段的全部数字见 [完整记录](PHASES_1_2.md)，没有用后续数据覆盖或删除不利结果。

第三阶段包括原始版、IK+BENG 版和仅 IK 版，预先固定全部六种排列，每种排列三轮，共 18 轮。每种版本在每个出场位置出现两次。每轮全新数据目录，统一启动后等待 20 秒，不穿插 SQL 回归。各版本六轮耗时均值的比较如下；三类内部各指标先平均，再对三类等权平均，负值不在单项层面截断。

| 版本 | 构建 | 分词 | 查询 | 综合 |
|---|---:|---:|---:|---:|
| 首次 FTS 修改前 | +0.00% | +0.00% | +0.00% | +0.00% |

最终选择版本在六个组内相对原始版的综合变化依次为：+1.15%, -10.41%, -8.61%, +11.19%, +5.24%, +3.65%。选择依据是这些完整实验及缩小未证实改动范围的考虑，不是统计显著性证明；同一批数据用于选择版本，不能将其当作独立验证得到的稳定收益。

最终选择后重新构建 `seekdb`、`oceanbase`，生成的服务端二进制与被测变体 **SHA-256 完全一致**：`8223c112ab56576470121b250fce34444bfb4fb4c24bbd57adf93da08c9f27e5`。

最终重新通过七组 C++ 检查，包含 3,336,192 项字符分类及 121,140 项停用词语义对照；936 项完整 SQL 结果核对一致，包括词元/词频、文档长度、完整命中 ID、相关性、top-k、DML 与回滚；四项 mysqltest 全部通过，原预期结果未改。这不等于整个官方套件或平台 CI 已通过。本次专用测试服务均已停止。

三种拆分变体、原始版和最终变体的逐次验证日志均保留。测试过程从未使用查询命中数量代替完整正确性验证。

## 条件与限制

统一参数为 `ROWS=20000 BATCH=500 ROUNDS=3000 QUERY_ROUNDS=200 SAMPLES=3 WARMUP=30 SKIP_LOAD=0`。每轮新报告、重新导入和建索引；未删异常样本，未扣除 SELECT 1 耗时。

环境为 WSL2 / Ubuntu 20.04、Clang 17、RelWithDebInfo；服务端绑定 CPU 12,14，客户端 CPU 10；`cpu_count=2`、`memory_limit=2G`。另一个既有实例保留运行，未擅自停止。每秒采集资源状态，但不能完整观测 Windows 宿主机干扰；CPU 绑定不等于独占 CPU。

此前 −169.70% 的严重退化没有以同样幅度重现，这并不能证明旧结果无效或确定根因。仍有运行和采样波动；仅 IK 版也出现 BENG 慢样本，因此不能仅凭早期英文分词退化断定 BENG 改动有缺陷。

增量构建保留的版本字符串和基准 `git_head/git_dirty` 不足以标识实验变体；以源码清单和二进制 SHA-256 为准。所有变体都是完整服务端构建，没有用测试对象替代生产构建。
