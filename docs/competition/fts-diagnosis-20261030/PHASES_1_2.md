# 全文索引调优：拆分对照与最终选择

日期：2026-10-30。仓库：`zoooey00/seek-db`，分支：`perf/fts-ik-beng-20261029`。

## 最终处理

**功能验证通过，但当前实验仍未证明稳定的综合性能提升，不能认定性能目标已经完成。**

撤回 `0668450` 新增的单次词频更新和 ASCII 停用词索引，保留此前的 IK/BENG 优化、生命周期修复及新增语义回归测试。两项新增优化分别测试和一起测试都未显示可靠的整机收益，因此不继续把局部 CPU 测试的改善当作提交依据。

当前生产源码恢复为 `965b5d35ec36218bffd2ece8442b2bf8038d4c9a` 的状态，测试和说明材料进一步完善。此处“恢复”不撤销此前 12 个 FTS 生产文件的优化，也不改动已有 AI 相关代码。最终重新构建的可执行文件 SHA-256 与先前保留的 `965b5d3` 可执行文件完全相同。

这是一项依据有限测量作出的保守选择，不是对退化根因的确定性证明，也不保证平台提分。之前的八轮结果继续保留，本次新增 24 轮，全部记录均保留，没有选择性删除。

## 实验一：分离两处新增改动

旧版为 `965b5d3`，完整新增版为 `0668450`；另外两版只启用其中一项改动。四种版本按预先固定的平衡顺序运行 16 轮，每个版本占据每个出场位置一次，每个有序的版本转换在组内出现一次。每轮创建全新数据目录、启动后等待 20 秒，并完整重新导入和建索引。全部性能测试结束后才执行 SQL 回归。

三类各自先平均单项下降比例，再等权平均。下表以四轮耗时均值比较，正数表示改善；对照对象是旧提交，不是平台固定基线。

| 版本 | 构建 | 分词 | 查询 | 综合 |
|---|---:|---:|---:|---:|
| 上一提交的生产源码 | +0.00% | +0.00% | +0.00% | +0.00% |
| 仅词频更新 | +0.81% | -9.16% | -3.96% | -4.10% |
| 仅 ASCII 停用词索引 | -0.19% | -7.00% | -5.90% | -4.36% |
| 两项同时启用 | +1.64% | -10.53% | -6.23% | -5.04% |

两项同时启用版在四个组内相对旧版的综合提升率分别为 -12.35%, +0.09%, -10.40%, -0.24%。结果有波动，缺乏可靠正收益，因此撤回两处新增生产改动。原始数据见 `evidence/ablation-summary.json`，协议见 `evidence/protocol.json`。

## 统一条件与已知限制

- 原始基准文件、生成数据、SQL、计时逻辑、评分脚本、固定基线和 CI 文件未修改。
- 参数为 `ROWS=20000 BATCH=500 ROUNDS=3000 QUERY_ROUNDS=200 SAMPLES=3 WARMUP=30 SKIP_LOAD=0`；每轮新报告，所有轮次有效且保留。
- WSL2 / Ubuntu 20.04，Clang 17，RelWithDebInfo；服务端 CPU 12,14，客户端 CPU 10；`cpu_count=2`、`memory_limit=2G`，专用端口 2901/2902。
- 每秒记录 CPU、内存、I/O 压力及数据库进程状态。测量窗口最少可用内存 6.48 GiB，最高内存压力占比 0.0022%，最高 I/O 压力占比 5.96%。记录没有显示明显内存不足，但这不能排除 CPU 频率、Windows 宿主机任务或其他调度影响。
- 另一个既有数据库实例保留运行，未擅自停止。CPU 亲和性不是独占 CPU；WSL 监控不能完整刻画 Windows 宿主机干扰。
- 未扣除 SELECT 1 耗时。旧实验严重退化未在相同幅度上重现，但不能据此断言旧结果无效或与代码无关。
- 增量构建保留的版本字符串及基准的 `git_head/git_dirty` 不能单独标识实验变体；以逐版本生产文件 SHA-256 和可执行文件 SHA-256 清单为准。最终二进制与已保存旧版逐字节一致。
